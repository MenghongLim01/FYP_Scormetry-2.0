ABSTRACT
This manuscript proposes the development of Scormetry 2.0: AI Rubric Generation and
Secure Document Management for Academic Evaluations to improve rubric-based defenses and
academic presentations at Paragon International University. In current practice, student reports
and slides are often shared through multiple channels such as Google Classroom, email,
messaging apps, or student devices. This leads to common issues during defense sessions,
including missing files, difficulty locating documents quickly, and opening the wrong version
under time-limited conditions.
The project introduces a centralized, web-based platform organized through
controlled-access team rooms. Students upload the final report and slides into one secure
location, while judges can access only the rooms assigned to them. Scormetry 2.0 also
implements a dynamic scoring workflow based on the official fixed rubric, where
criterion-by-criterion scoring and automatic calculation reduce manual setup time and minimize
formula or weighting errors commonly seen in spreadsheet-based scoring.
To preserve standardization, Scormetry 2.0 includes an AI-assisted rubric
PDF-to-dynamic conversion process with organizer verification and rubric locking before
scoring begins. Scores and feedback (comments, notes, and follow-up points) are stored together
in one centralized record for post-defense review. The system is developed iteratively and
evaluated through user acceptance testing aligned with selected ISO/IEC 25010 quality
characteristics to assess usability, security, reliability, and overall fitness for ParagonIU
evaluation tasks.

8.1 Rationale / Background of the Study
Final Year Project (FYP) defenses and academic presentations at Paragon International
University involve multiple teams, judges, and strict time constraints. In practice, student
documents (reports and slides) are often scattered across messaging apps and shared drives,
leading to missing files, wrong versions, and delays during defense sessions. Additionally, rubric
setup and score consolidation are frequently done manually, which is time-consuming and prone
to calculation errors—especially when there are many criteria and judges. These challenges
reduce evaluation efficiency, increase stress during the event, and make post-defense review
difficult. Scormetry 2.0 was developed to address these issues by providing controlled access to
documents, verified dynamic rubric conversion, and centralized scoring and feedback in one
platform.

8.3 Findings
Based on the results of system development, functional testing, and evaluation using
realistic academic defense scenarios, the following findings were obtained:
1. Scormetry 2.0 addressed the main development challenges related to secure document
handling, controlled access, Dynamic Rubric scoring, AI-assisted rubric conversion,
review locking, score release, and centralized evaluation records.
2. The controlled-access Team Room workflow restricted documents and evaluation records
to authorized users only. Teachers could manage subjects, teams, reviewers, and
submissions, while judges/reviewers and students could access only their assigned or
approved records.
3. Centralized document storage improved access to correct final student papers before and
during defense sessions, reducing reliance on scattered channels such as email,
messaging apps, and external drives.
4. The Dynamic Rubric module supported criterion-based scoring, automatic calculation,
feedback entry, and review submission, reducing manual scoring workload and common
computation errors.
5. The AI-assisted rubric conversion workflow helped generate a Dynamic Rubric draft
from the official rubric PDF, while teacher verification and locking preserved the
approved rubric structure.
6. Usability evaluation showed that Scormetry 2.0 supports the main tasks of teachers,
judges/reviewers, and students in document access, scoring, feedback, and post-defense
review.

8.4 Conclusions
Based on the findings, the following conclusions are presented:
1. Scormetry 2.0 extends the original Scormetry concept into a more complete evaluation
support system by adding secure document handling, controlled Team Room access,
Dynamic Rubric scoring, AI-assisted rubric conversion, review locking, and centralized
records.
2. Role-based and assignment-based access control is suitable for protecting student
documents and evaluation records because users can only access functions and records
related to their roles and assigned Team Rooms.
3. Centralized Team Room document storage improves defense readiness by reducing
missing files, wrong versions, and delays in locating final student papers.
4. A locked Dynamic Rubric with automatic calculation improves scoring accuracy and
reduces manual workload, especially during multi-judge evaluations.
5. AI-assisted rubric conversion can speed up rubric preparation, but teacher verification
and locking are necessary to preserve the official rubric structure before scoring.

8.5 Recommendations
Based on the conclusions, the following recommendations are proposed:
1. Improve defense readiness and document compliance by adding a defense checklist,
upload deadline reminders, and final-version confirmation so teams submit required
documents before the defense and judges can review them in advance.
2. Enhance rubric governance by supporting rubric variations for different departments or
programs while maintaining the verification and locking workflow to prevent unapproved
changes during scoring.
3. Add reporting and analytics features such as PDF/Excel export, submission status
dashboards, scoring summaries, judge participation tracking, and feedback reports to
support post-defense review and academic decision-making.
4. Develop a mobile application version of Scormetry 2.0 for greater convenience. A mobile
app can help students upload documents, judges access assigned Team Rooms, and
organizers monitor evaluation progress more easily using smartphones or tablets.
5. Integrate QR code-based access for future academic events. QR codes may be used for
quick room access, voting, judging, attendance confirmation, or event feedback, allowing
users to submit evaluations or comments through their own devices while keeping results
centralized for review and reporting.

CHAPTER 1
INTRODUCTION
This chapter presents the background of the study and the current evaluation practices
used in Final Year Project (FYP) defenses and other academic evaluations at Paragon
International University. It discusses challenges in document handling and rubric-based scoring,
introduces Scormetry 2.0 as the proposed solution, and states the project’s problem, objectives,
significance, and scope and limitations.
1.1 Context Of The Study
Paragon International University conducts many rubric-based academic evaluations,
including Final Year Project (FYP) defenses, class presentations, and other assessments
involving multiple judges and evaluation teams. In practice, these evaluations often rely on
separate tools for document sharing, scoring, and feedback, resulting in a fragmented workflow
that can be time-consuming, inconsistent, and difficult to manage efficiently. Brookhart (2018)
explained that “True rubrics feature criteria appropriate to an assessment’s purpose”; therefore,
the fairness and consistency of rubric-based evaluation depend not only on the rubric itself but
also on the ability of evaluators to access and apply it properly in real assessment settings. Red
Deer Polytechnic (2023) further noted that “Rubrics can reduce grading and feedback time and
ensure shared expectations”. Nevertheless, delays may still occur when final student documents,
scoring instruments, and feedback records are not centralized, especially during time-sensitive
defense sessions.
The original Scormetry (2025) project provided the initial foundation for addressing this
issue by focusing on digital score tabulation for rubric-based evaluations at Paragon International

University. The system helped reduce manual scoring work and improved the organization of
evaluation results. Based on this existing foundation, Scormetry 2.0 is not a completely new

AI-assisted transformation of the official rubric PDF into a dynamic rubric for scoring without
changing its approved structure, and centralized storage of scores and judge feedback for
post-evaluation review. In this way, Scormetry 2.0 strengthens and expands the original
Scormetry system into a more integrated platform for managing rubric-based academic

1.3 Project Description
Scormetry 2.0 is a web-based evaluation support system for Paragon International
University designed for rubric-based academic evaluations such as Final Year Project (FYP)
defenses and similar presentations. The system organizes each evaluation through
controlled-access Team Rooms, where authorized users collaborate and manage evaluation
materials in one centralized workspace. Student teams upload the final report and presentation
slides to their assigned Team Room, while judges can access only the Team Rooms assigned to
them for document review and scoring.

===== PAGE 26 =====
26
Scormetry 2.0 implements an AI-assisted official rubric PDF-to-Dynamic Rubric
conversion workflow that transforms the fixed department rubric into a structured rubric format
for criterion-by-criterion scoring. To preserve standardization, the converted Dynamic Rubric
undergoes organizer verification and is locked before scoring begins to prevent unverified
changes during evaluation. Judges then submit scores per criterion using the locked Dynamic
Rubric, and the system automatically calculates totals and tabulates results to reduce manual
computation and common weighting or formula errors.
In addition to scoring, Scormetry 2.0 centralizes evaluation outputs by storing judge
feedback (comments, notes, and follow-up points) together with scoring records and uploaded
documents inside the Team Room. This supports organized post-defense review, improves
evaluation readiness during time-limited sessions, and maintains secure, retrievable evaluation
records for documentation purposes.

1.6 Scope And Limitation Of The Study

academic evaluations at Paragon International University, particularly Final Year Project (FYP)

2.1 Development Boundaries and Implementation Challenges
Ndibalema (2022) reports that the transition to online distance learning in
developing-country higher education institutions was “challenged with unstable network
connection” and unaffordable bandwidth, emphasizing that effective implementation requires
stable and affordable internet accessibility. In defense settings where time is limited, unstable
connectivity can affect document availability and timely access to files needed for evaluation.
Currier et al. (2004) emphasize that “Metadata enables users to find the resources they
require.” In academic evaluation contexts, consistent labeling and structured organization (e.g.,
team name, document type, version, upload date, and timestamp) support faster retrieval and
reduce the risk of opening an incorrect or outdated version during the defense.
The literature highlights that reliable access and structured organization are essential to
ensure that required documents can be located quickly in time-sensitive academic settings.
Connectivity limitations can affect real-time access, while metadata and consistent labeling
improve file retrieval and reduce confusion. These findings support Scormetry 2.0’s use of

2.2 Controlled Access and Document Retrieval
Sandhu et al. (1996) explain that “permissions are associated with roles, and users are
assigned to appropriate roles.” This describes role-based access control (RBAC), where access is
managed through defined roles such as Judge, Student, and Organizer/Teacher, which is relevant
for protecting evaluation materials that should not be publicly accessible.
Hu et al. (2014) define ABAC as “a logical access control methodology where
authorization to perform a set of operations is determined by evaluating attributes associated
with the subject, object, requested operations, and, in some cases, environment conditions
against policy.” This enables more specific access decisions using attributes such as team
identification, judge assignment, event/defense context, and document type, which is applicable
for restricting access to Team Rooms and evaluation records.
RBAC and ABAC establish that secure systems require structured authorization rules to
ensure that only permitted users can access protected information. RBAC supports role-based
restrictions (e.g., teacher vs. judge vs. student), while ABAC supports more granular restrictions
based on assignments and contextual attributes (e.g., which judge is assigned to which Team
Room). These models support Scormetry 2.0’s controlled-access design, where documents and
evaluation records are accessible only to authorized users based on roles and assignments. As a
result, Scormetry 2.0 aligns with SOP 1 by reducing unauthorized access and improving
confidentiality and integrity of evaluation materials.

2.3 Functional and Non-Functional Requirements
Brookhart and Chen (2014) emphasize that “rubrics yield information of sufficient
quality if certain conditions are met, most notably having clear and focused criteria.” This
highlights the importance of implementing the official fixed rubric in a clear and consistent
Dynamic Rubric format so that judges can apply the criteria reliably and consistently across
teams.
Maditinos et al. (2012) warn that “errors contained in most spreadsheets may be
catastrophic and difficult to detect.” This highlights the risk of manual spreadsheet-based
scoring, where incorrect weights, formulas, or computation steps may affect final results. A
Dynamic Rubric with automatic calculation can reduce these errors by standardizing the scoring
structure and computing totals consistently.
The literature supports that rubric effectiveness depends on clarity of criteria and

to errors that may be difficult to detect during real evaluation sessions. These findings justify
Scormetry 2.0’s Dynamic Rubric approach, which presents criterion-by-criterion scoring based

standardizing scoring inputs and calculations, Scormetry 2.0 supports SOP 3 through improved
scoring accuracy and reduced setup workload.

3.4.3. System Architecture
3.4.3.1 Network Model
Fig. 39. Network Model Diagram
Figure 39 indicates the network model of Scormetry 2.0, which includes the main
components and external services needed for the system to function properly. The system allows
teachers/admins, judges/reviewers, and students to access the platform through a browser using
the Scormetry domain. The major components are explained below:
● Cloudflare DNS / HTTPS: Routes users to the Scormetry 2.0 system domain and
provides HTTPS support for secure access.
● Google OAuth: Provides authentication by allowing teachers/admins, judges/reviewers,
and students to log in using their Google accounts.

===== PAGE 104 =====
104
● Mail / SMTP: Sends system emails such as student invitations, reviewer invitations, and
other notification messages.
● Laravel Backend: Handles the main system logic, including user authentication,
authorization, Team Room management, document access, rubric processing, scoring,
feedback, and score release.
● Frontend: Provides role-based panels for users. The Teacher Panel manages subjects,
teams, rubrics, and results; the Judge Panel supports document review and scoring; and
the Student Panel supports document upload and result viewing.
● Database: Stores system records such as users, subjects, teams, papers, rubrics, reviews,
feedback, and system settings.
● Private File Storage: Stores uploaded official rubric PDFs and student final paper PDFs.
Access to these files is controlled through the Laravel backend.
● OpenAI Responses API: Supports AI-assisted conversion of the official rubric PDF into
a Dynamic Rubric draft for teacher/admin verification and locking.

===== PAGE 105 =====
105
3.4.3.2 Network Topology
Fig. 40. Network Topology Diagram
Figure 40 shows the network topology of Scormetry 2.0, which represents how user
requests travel from the end user to the application server. The topology is designed to provide
secure routing, traffic filtering, and controlled access to the Scormetry 2.0 virtual machine. The
main components are explained below:
● End User: Represents teachers/admins, judges/reviewers, and students accessing
Scormetry 2.0 through a web browser.
● Cloudflare Firewall: Serves as the first protection layer for the system. It helps manage
DNS, HTTPS access, and basic protection against malicious traffic.
● Firewall: Filters incoming and outgoing traffic before requests reach the internal
network. It helps prevent unauthorized access to the application environment.

===== PAGE 106 =====
106
● Cloud Router: Directs network traffic between the firewall, proxy server, managed
switch, and Scormetry 2.0 virtual machine.
● Proxy Server: Acts as an intermediary between the external request and internal
services. It may help route traffic, manage access, and improve request handling.
● Managed Switch: Connects the virtual machine and internal network components,
allowing controlled communication inside the server environment.
● Scormetry 2.0 Virtual Machine: Hosts the Scormetry 2.0 application, including the
frontend panels, Laravel backend, database connection, and private file storage used for
academic evaluation workflows.
3.4.3.3 Security
Fig. 41. Security Model Diagram
Figure 41 shows the security model of Scormetry 2.0. The system applies several
protection layers to secure access, user requests, documents, and evaluation records. User traffic

===== PAGE 107 =====
107
first passes through Cloudflare Firewall, which supports DDoS protection and automatic HTTPS
redirection before requests reach the system firewall.
After authentication through Google OAuth, users access the system through role-based
panels: Teacher Panel, Judge Panel, and Student Panel. The Laravel backend verifies
permissions, roles, and session tokens before allowing any protected action. This ensures that
only authorized users can access Team Rooms, uploaded papers, rubrics, scores, and feedback
records. The backend also applies secure configuration, input validation, exception handling, and
database protection to maintain the confidentiality and integrity of sensitive evaluation data.
